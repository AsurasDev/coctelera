# Implementation Plan: Coctelera — Base de Datos Brutalista de Cócteles

**Branch**: `001-coctelera-brutalist-db` | **Date**: 2026-06-06 | **Spec**: [spec.md](./spec.md)

**Input**: Feature specification from `specs/001-coctelera-brutalist-db/spec.md`

## Summary

Sitio web de base de datos de cócteles con diseño brutalista (Simuu v2). Frontend Astro generado estáticamente en build-time con datos de Directus CMS. El usuario nunca hace peticiones al backend — todo el contenido se incrusta en HTML estático. Datos iniciales importados desde el repositorio bar-assistant/data. Desplegado en Railway (Directus + Astro). Filtros y búsqueda funcionan en cliente via Alpine.js con datos incrustados en el HTML.

## Technical Context

**Language/Version**: TypeScript / Node.js 20, Astro 4.x

**Primary Dependencies**:
- `astro@4.x` — SSG framework
- `@astrojs/alpinejs` + `alpinejs@3.x` — client-side filtering/search
- `@directus/sdk` — build-time data fetching
- `tsx` — TypeScript runner for import script
- `serve` — static file server for Railway

**Storage**: PostgreSQL 16 (Railway plugin) for Directus, Directus Files for images

**Testing**: Vitest (unit/logic), Playwright (E2E validation of built site)

**Target Platform**: Modern browsers (Chrome, Firefox, Safari, Edge last 2 versions), Railway hosting

**Project Type**: Web application — static frontend + headless CMS backend

**Performance Goals**: LCP < 2.5s, FID < 100ms, CLS < 0.1 (Core Web Vitals). Gallery load < 3s. Detail load < 2s.

**Constraints**: Zero client-side API calls to Directus. 100% static output from Astro.

**Scale/Scope**: ~200+ cocktails from bar-assistant/data → ~200+ static HTML pages. Single language (es-CO).

- Configure Directus webhook → Railway deploy hook

### Phase G: GitHub Repository
- Create public GitHub repo `coctelera`
- Initial commit + push
- Verify Railway auto-deploy on push
